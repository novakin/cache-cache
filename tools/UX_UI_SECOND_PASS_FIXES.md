## Follow-up: Save cancellation recovery

A genuine browser click exposed a pending-state race. The shell marked the form busy, then checked cancellation in a microtask. Native event propagation can run that microtask before later document/window submit listeners cancel the event, leaving Saving and Working feedback stuck. The existing synthetic `page.evaluate(requestSubmit)` test kept all listeners in one JavaScript stack and missed that timing.

The cancellation check now runs in the next event-loop task, after submit propagation. A canceled submission removes pending/busy markers, retains edited fields and their section review, restores departure protection and permits retry. The shared Save-state synchronizer also owns the button label, so page-navigation synchronization retains Saving while a request is pending. Native form endpoints, fields and submitter values remain authoritative. This is cancellation recovery; it does not declare a stalled or failed network request saved, retry it automatically or unlock an in-flight write on a timer.
