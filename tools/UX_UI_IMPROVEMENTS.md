## Rating method and baseline

Baseline expert rating: **visual UI 65/100, task UX 45/100, combined 55/100**. The combined rating is their equally weighted average. Scores are reviewer judgments with coarse precision, not instrumented measurements or a usability-study result. Visual UI considers hierarchy, spacing, typography, responsive composition, and theme consistency. Task UX considers findability, setup/verification/recovery, transaction clarity, feedback, and keyboard behavior. A high score requires evidence for those categories, not fidelity to a mockup.

## Design direction

NoobRocket is an operational WordPress tool. The interface should help an owner answer: what is enabled, what needs attention, what will this action change, and how can I verify or undo it? Expert details stay available without dominating ordinary tasks.

- **Palette:** retain Paper `#ffffff`, Canvas `#f3f6fc`, Ink `#182943`, Slate `#53647d`, Flight Blue `#3157ce`, and existing semantic attention colors. Dark uses the current paired navy surfaces and readable light text. No decorative gradients or new font dependencies.
- **Type:** system UI family; clear 28px page titles, 17–18px section titles, 14px routine settings, and 15–16px mobile reading/input text. Maintain readable measures and visible focus.
- **Layout:** all native destinations directly visible, with provider setup beside Integrations. Persistent compact navigation; left-aligned settings, closely paired controls, quieter section boundaries, and a clear bottom save boundary. Mobile uses one short header, visibly named Settings navigation, and reachable controls.
- **Components:** primary actions commit a clearly described change; secondary links navigate; native disclosures contain evidence and expert detail. Routine checkbox controls sit next to their labels. Data tables remain tables on desktop and explicit labeled records on mobile.
- **Identity:** the rocket and blue accent provide the recognizable mark. The product earns distinction through precise operational content and coherent behavior rather than oversized cards, ornamental type, or animation.

The proposed direction was checked against the real product. A repeated card grid would preserve the audited flat hierarchy, so routine rows are tightened and attention, evidence, and workflow boundaries receive different treatment. Native WordPress form and security boundaries remain intact. The original mockup is not a requirement.

## Acceptance boundary

Implement the audited improvements at their responsible layers, preserve optimization settings and public visitor behavior, and verify current UI output in both themes and English/French. Use populated/empty data, enabled/disabled integrations, clean/dirty forms, keyboard navigation, and widths from 320 to 1440px. Verify consequential handler changes with isolated focused tests. No actual provider change or destructive cleanup on the user's local preview. Stop when implemented task flows and visual states pass review without material unresolved defects; remaining research limits must be stated honestly.
