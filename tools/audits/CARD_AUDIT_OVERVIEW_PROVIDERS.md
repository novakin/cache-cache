# Overview and provider card audit — 9 October 2026

Read-only audit of Overview, Integrations, Cloudflare and Sucuri. This is an improvement proposal, not an implementation or a numerical design score. Review uses the current templates, frontend behavior and [design guidelines](../DESIGN_GUIDELINES.md), with UI/UX Pro Max, Frontend Design and Design System principles. Existing fixes separating dashboard actions from navigation and removing the detached worker footer are preserved and excluded from the findings.

## Evidence status

Source review and direct visual inspection are complete for the assigned routes. Baseline native cards and expanded disclosures were reviewed in English at 1440px and French at 390px, in light and dark. Additional disabled/configured providers, unverified/problem/ready Overview states and selected French 320px cards were inspected. [Capture inventory](../../.artifacts/card-audit-20261009/inventory.json) retains labels, geometry, controls and individual card crops. The root audit collected 448 render states and 1,526 card tiles across 70 configurations across all 14 routes; these totals describe collection, not proof that every interaction passed.

Request-only fixtures provide representative unavailable, configured, failed and completed states; their credentials, grades and job counts are synthetic, not site performance measurements. No provider purge, queue action, API request or settings save is part of this audit. The root collector reported zero page script errors, document overflow or local operation requests. This does not eliminate the layout and comprehension findings below.

## Findings and proposals

| ID / priority | Evidence and consequence | Smallest coherent improvement | Acceptance |
| --- | --- | --- | --- |
| OP01 / P2 — Preload states overstate progress | `local-css-diagnostics.php` chooses “Queue complete” whenever enabled with no pending/running/failed entries, even when completed count is zero and no completion is evidenced. Disabled or paused states still say “Queued pages load in small, automatic batches.” A new user can read an empty queue as a successfully warmed site or assume paused warming continues. Source confirmed; operational failure is not claimed. | Use “No queued pages” without completion evidence. Choose purpose copy from the same off/paused/active state as the heading; paused copy explains preserved pending work, off copy points to enabling warming. | Unstarted zero-count, completed, disabled, paused and failed states all make truthful claims and retain their current navigation/actions. No new queue mechanism. |
| OP02 / P2 — Provider prerequisite confuses draft and saved state | `PageManager::syncProviders()` gates configuration using the current unsaved switch. `provider-prerequisite.php` always says the provider “is off in saved settings.” Turning a saved-on provider off without saving makes that statement false. Enabling a saved-off provider exposes configuration while its cache operation still correctly uses saved credentials. | Distinguish saved readiness from pending integration changes in copy, using the server-rendered saved state and existing dirty-state model. Keep the connection form reachable in the current draft; explicitly say save is required before cache operations. | Saved off/on and draft off/on permutations accurately name what is saved and pending. Cancel restores the correct prerequisite without saving. Cache actions continue to use saved values. |
| OP03 / P2 — Credential errors identify the page, not the field | Provider validation notices are relocated to the owning route and focused, which is useful. The shared text template does not connect those notices to the invalid secret field or set its invalid state. For Sucuri the failing field is unambiguous; a missing Cloudflare Zone ID is also identifiable, while a general authorization failure can belong to the whole credential group. | Keep the focused route summary, add a link to identifiable invalid fields, and attach concise inline error text through `aria-describedby`/`aria-invalid`. Keep account-wide authorization failures at group level rather than guessing the culprit. | Sucuri format error and missing Zone ID name and link their input; screen-reader focus on the input announces the error. General authorization errors remain discoverable without marking innocent fields. |
| OP04 / P2 — Modern image headline hides availability and progress | `image-generation.php` can show an amber “Enabled” badge when no encoders are available or attachments failed. Its unconditional AVIF/WebP sentence implies both formats, although the backend accepts either supported encoder. Before and after a completed scan, its idle helper is the same “Ready to scan your media library.” Existing `last_run`/`generated` state is not exposed. | Separate feature state from operational health in the visible status: off, encoder unavailable, queued, needs attention, idle/completed. Name supported output formats. Reuse the existing last-run data in evidence so the user can see that generation progressed. | Off, AVIF-only, WebP-only, no-encoder, pending, failed and completed states identify available formats and a useful next step. Completion evidence is not presented as proof that every source image was converted. No new job service or log. |
| OP05 / P3 — Worker setup repeats and leaves the interface for raw Markdown | When a worker is required, the immediate “Set up scheduled worker runs” link and the auto-open Server worker’s “Worker setup and scheduling” link point to the same README. Read-only GET confirmed HTTP 200 with `text/markdown; charset=UTF-8`, not a rendered guide. This is within the correct card, but repeats the destination and makes the setup handoff harder to read. | Keep one setup destination inside the visible worker report. Point its primary help link to the existing rendered `docs/index.html#css` overview; retain README as a clearly named advanced reference there. | Worker-required state has one obvious setup destination. It opens a readable guide whose first section explains prerequisites and next action. No duplicate detached footer link. |
| OP06 / P3 — Original CSS recovery has unexplained disabled action | Recovery is always present, but its regeneration button is disabled in Original CSS. The explanation describes regeneration without saying why it cannot run. | Hide this recovery row when CSS generation is off, or state that a generation mode must be chosen before regeneration is available. | In Original CSS, there is no unexplained disabled recovery operation. Enabled modes retain scope and fallback information. |
| OP07 / P3 — Cloudflare settings use vague labels | “Optimal settings” is an unexplained value judgment in the control label; its useful description now lists exact changes. “Relative protocol” names syntax rather than its task. The folded specialist group is otherwise appropriate. | Rename controls around concrete intent, for example “Apply recommended zone settings” and “Rewrite static URLs for Flexible SSL,” while retaining the exact on-save effects and restoration qualification. | A user can identify each switch’s task from its label; detailed effects remain beside it, correctly translated and visible before save. |
| OP08 / P3 — Object cache retains the older navigation style | Fresh light/dark card crops show a permanently underlined “Object-cache setup and troubleshooting” link in `.noobrocket-status-actions`. Preloading, CSS, Images and PageSpeed navigation now use divided chevron footers. This card looks like an unfinished version of the same app. | Reuse `.noobrocket-status-navigation` for its supporting destination. Keep inline links inside genuine sentences; do not restyle every text link as a button. | Object cache uses the same navigation placement, target, focus and hover treatment as adjacent dashboard cards in both themes. |
| OP09 / P3 — Deep CSS evidence stretches unrelated summary content | Expanded desktop Site status gives Preloading and CSS equal 750px panels, while Preloading content ends hundreds of pixels earlier. Default footer positions differ too. Modern images/Object cache likewise stretch to the taller neighbor. Actual captures confirm large empty regions; unequal content length is expected, compulsory empty-card height is not useful. | Keep compact operational summaries together and let substantial worker/failure evidence occupy a full-width supporting region in source order, still owned by CSS. Use consistent navigation footers. Avoid forcing unrelated task surfaces to equal heights or introducing masonry. | Opening CSS evidence does not produce several hundred pixels of empty Preloading panel. The shared cache-first hierarchy and source/keyboard order remain intact; no card per counter. |
| OP10 / P3 — Desktop credential labels and helper links are remote from inputs | Desktop Cloudflare/Sucuri cards place labels/acquisition links at the left edge and 320px inputs at the far right, leaving roughly 550px between the API label and its input. Mobile’s stacked version groups them more clearly. This weakens visual association despite correct HTML labels. | Use one bounded credential form column, with label directly above or immediately beside its input and acquisition/help text beneath that same field. Preserve aligned field widths and native secret controls. | Label, entry and its acquisition link read as one group at desktop and narrow sizes. No arbitrary half-width paragraph columns; long email/Zone ID remain usable. |
| OP11 / P3 — Wrapped provider identity moves the switch between tasks | French 390/320px provider rows wrap Configure connection below logo/name. The centered switch then sits between the name and navigation line rather than beside the name. Optional integration rows keep a clean name/switch baseline, so the provider group feels inconsistent. | Give identity/name and enable switch one row. Place Configure connection in the next supporting line, independent of the switch’s alignment. Keep the link reachable while off. | Cloudflare/Sucuri switches align with their provider name at 1440/390/320px; Configure connection is distinct and no target overlaps. |
| OP12 / P3 — Integration group labels and introductory gaps add little hierarchy | “Optional integrations” and “Available integrations” have near-identical instructions, though one group contains cache compatibility and the other credential-based providers. The first row is separated from the introduction by a large gap; the disabled legacy WebP row still starts with a generic benefit statement before its concrete unavailable reason. Direct baseline crops confirm excess introduction space and repetitive naming. | Use task-specific headings such as “Cache compatibility” and “Provider connections,” shorten repeated save instructions to one page-level cue, reduce first-row gap and name legacy WebP compatibility explicitly. | The two groups are distinguishable without reading every row. The unavailable WebP reason remains visible and modern image delivery does not appear broken. Keep one grouped surface per task. |
| OP13 / P3 — Legacy button movement and margins survive the new component | Source trace: `noobrocket-settings.css` button hover/focus block sets `translateY(-2px)`; its `.noobrocket-field .noobrocket-button` rule sets `margin: 8px 0`. The shared admin button override at `noobrocket-admin.css` normalizes color, padding and shadow but not transform/margins. French PageSpeed’s wrapped Replace/Remove buttons have a 26px gap instead of the action-row 10px. The final shared browser probe confirms exactly 2px movement on hover/focus at 320/390/1440px in both themes, including reduced motion. | Normalize transform and margins at the shared app button component; let action rows own spacing. Keep visible focus and pressed/hover colors without moving bounds. | Measured button bounds do not move on hover/focus, including reduced motion. Wrapped action-row spacing follows its token once, and Tools/provider buttons retain their correct containment. |
| OP14 / P3 — Provider cache and disclosed Help placement use inconsistent rows | At French 390px, Cloudflare’s longer title/action wraps into two rows while Sucuri remains side-by-side; at 320px Sucuri changes again. Expanded Cloudflare settings places its lone Help link in a separate 44px row before the first switch, unlike header Help elsewhere. These are observed presentation discrepancies, not failed operations. | Apply one explicit narrow-screen action layout to both provider cards. Keep help out of disclosure summaries, but place it in a compact supporting footer rather than a lonely leading row. | Provider operations share heading/prerequisite/action order at narrow sizes. Expanded groups expose Help in a predictable supporting location without an empty leading band. |

P2 means a meaningful comprehension or recovery gap. P3 means lower-risk clarity or presentation improvement. No source finding above proves live provider authorization, queue execution or site delivery failed.

## Boundaries and unanswered checks

Screenshots alone cannot prove screen-reader announcements, provider authorization, queue throughput, real PageSpeed grades or backend recovery. General credential validation and unsaved provider permutations are source-confirmed, with root shared interaction evidence recorded separately. A single-encoder image server and long namespaced object-cache provider name were not directly exercised; OP04’s format claim is confirmed by source conditions. Forced French screenshots still show English-formatted core dates and decimal separators; source correctly uses `wp_date()`/`number_format_i18n()`, so this is recorded as a locale-fixture/core-catalog limitation rather than an invented plugin formatting defect.

The findings should be fixed at their current owners, without replacing the palette or typeface, adding a new state framework or constructing a separate documentation engine. Both current themes remain readable; the material work is hierarchy, truthful state, visual proximity and consistent shared components. No UI code, package or live deployment changed in this audit.
